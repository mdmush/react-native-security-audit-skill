# iOS project review

Covers the native iOS half of the `platform` domain, plus iOS-specific parts of `privacy`. Applies when `ios/` exists. If it is generated by Expo prebuild and untracked, read [expo.md](expo.md) first.

## Which files, which configuration

| File | Why it matters |
|---|---|
| `ios/<App>/Info.plist` | URL schemes, ATS, file sharing, usage descriptions, background modes |
| `ios/<App>/<App>.entitlements` (sometimes separate Debug/Release files) | Associated domains, keychain groups, app groups, data protection, push environment |
| `ios/<App>/AppDelegate.(swift\|mm\|m)` | URL handling, bundle URL, networking and RN bridge setup |
| `ios/<App>/PrivacyInfo.xcprivacy` | Declared data collection and required-reason API use |
| `ios/Podfile`, `Podfile.lock` | Pod sources, `use_frameworks`, Hermes, post-install hooks |
| `ios/<App>.xcodeproj/project.pbxproj`, `*.xcconfig` | Per-configuration build settings, embedded files, run-script phases |
| Extension targets (share, notification service, widgets) | Each has its own plist and entitlements, and usually shares data through an app group |

Xcode has Debug and Release configurations. `#if DEBUG` blocks and Debug-only xcconfig values do not ship. Entitlements can differ per configuration: check which file each configuration references in `project.pbxproj` (`CODE_SIGN_ENTITLEMENTS`).

Some facts are only in the signed binary or the Apple developer account: the final entitlements after provisioning, whether the associated domain's `apple-app-site-association` file lists the app. Treat them as `needs_validation`.

## Info.plist

**App Transport Security** (`NSAppTransportSecurity`).

- `NSAllowsLocalNetworking` true, and a `localhost` exception domain: template defaults for Metro. Fine.
- `NSAllowsArbitraryLoads` true: disables ATS for the whole app. Apple applies it in all configurations unless the plist is varied per build. On its own a hardening note; with real cleartext traffic, part of a `network` finding ([network-and-auth.md](network-and-auth.md)).
- `NSAllowsArbitraryLoadsInWebContent`: same, for WebViews only.
- `NSExceptionDomains` with `NSExceptionAllowsInsecureHTTPLoads` or lowered `NSExceptionMinimumTLSVersion` for a production host: cite the host and what the app sends there.

**URL schemes** (`CFBundleURLTypes` → `CFBundleURLSchemes`). iOS does not let an app own a custom scheme; if two apps register one, which gets the URL is undefined. That matters when something secret is delivered through the scheme (OAuth redirects, magic links). What the links do once received is in [platform-entry-points.md](platform-entry-points.md). Schemes added for SDKs (`fb...`, `com.googleusercontent.apps...`) are expected.

**`LSApplicationQueriesSchemes`**: schemes the app may probe with `canOpenURL`. A long list can be a privacy note (app-installed fingerprinting); nothing more.

**File exposure.** `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` make the app's Documents directory visible in the Files app and Finder. Check what the app writes there: SQLite databases, exported reports, logs and cached media are common. `device-access` attacker; rate by the data.

**Usage descriptions** (`privacy`). Each `NS...UsageDescription` key marks a protected resource the app or a library can request. Check for a feature behind each, especially location-always, contacts, microphone, tracking (`NSUserTrackingUsageDescription`), local network and Bluetooth. Unused ones are store-review and privacy notes.

**Background modes** (`UIBackgroundModes`): location and VoIP modes without a matching feature are privacy notes.

## Entitlements

- **`com.apple.developer.associated-domains`** (`applinks:`, `webcredentials:`): Universal Links and shared web credentials. Present for the domains used in sensitive callbacks is good practice. `?mode=developer` suffixes should not be in the release entitlements.
- **`keychain-access-groups`** and **`com.apple.security.application-groups`**: every app and extension in the group can read the shared keychain items and container. Fine within one team's apps; check what is placed in an app-group container, since it gets the container's (often weaker) file protection and is readable by all extensions.
- **`get-task-allow`** true: allows debugger attachment. Correct in the Debug entitlements; Xcode strips it for App Store distribution. Only a finding if hard-coded in a Release entitlements file used for ad hoc or enterprise distribution.
- **`aps-environment`**: `development` vs `production` is set by signing; not a finding.
- **`com.apple.developer.default-data-protection`**: if set to a class weaker than the default (`NSFileProtectionCompleteUntilFirstUserAuthentication`), note it. Setting `NSFileProtectionComplete` is a hardening recommendation for apps with sensitive files, with the caveat that background tasks cannot read such files while the device is locked.

## Native code

Read `AppDelegate` and anything that is not template code.

- **URL entry points**: `application(_:open:options:)` and `application(_:continue:restorationHandler:)` normally just forward to `RCTLinkingManager`. Custom logic there (parsing the URL and acting before JS sees it) deserves a full read.
- **Bundle location**: `bundleURL()` / `sourceURL(for:)` should return the Metro URL under `#if DEBUG` and the embedded `main.jsbundle` otherwise. A release path that loads a bundle from the Documents directory, a downloaded file or a remote URL without signature verification is code execution for whoever controls that source. See OTA in [supply-chain-and-release.md](supply-chain-and-release.md).
- **TLS challenge handling**: `urlSession(_:didReceive:completionHandler:)` or the Obj-C `didReceiveChallenge` returning `.useCredential` with `URLCredential(trust:)` and no evaluation of the trust object disables certificate validation. Genuine pinning code has the same shape but compares keys or certificates first. Also `RCTSetCustomNSURLSessionConfigurationProvider`. See [network-and-auth.md](network-and-auth.md).
- **Keychain calls**: `kSecAttrAccessibleAlways*` (deprecated, readable while locked); missing `ThisDeviceOnly` for secrets that should not migrate; access control flags for biometric binding.
- **Custom native modules** (`RCT_EXPORT_METHOD`, Swift `@objc` methods, TurboModules): trusted when called by the app's own JS, attack surface when JS forwards untrusted input. Look for file paths, `NSTask`-like execution, `performSelector` with dynamic names, `NSPredicate(format:)` with interpolated input, and `UIApplication.open` on unchecked URLs.
- **Pasteboard**: writing secrets to `UIPasteboard.general`; reading the pasteboard on launch (privacy prompt and data exposure).
- **Logging**: `NSLog`/`os_log` of tokens or request bodies outside `#if DEBUG`. `NSLog` output is readable from a connected Mac.
- **WKWebView in native code**: `isInspectable = true` without a debug guard, `allowFileAccessFromFileURLs` via KVC, script message handlers (`WKScriptMessageHandler`) that act without checking `message.frameInfo.securityOrigin`.

## Extensions and shared containers

Share extensions, notification service extensions and widgets run as separate processes with their own attack surface:

- A share extension receives arbitrary content from other apps. Follow it as untrusted input.
- A notification service extension decrypting or rewriting pushes needs keys; check where they are stored (shared keychain group) and what it logs.
- Widgets render data from the app-group container; that data is visible on the lock screen unless the widget marks it privacy-sensitive.

## Privacy manifest and tracking

`PrivacyInfo.xcprivacy` declares collected data types, tracking domains and required-reason API usage. Mismatches between the manifest, the App Store privacy label and what analytics/ads SDKs actually send are compliance issues: report them under `privacy` as `needs_validation` or hardening, with the SDK calls you found (see user-data leads from the scanner). An app that reads the advertising identifier or tracks across apps without requesting App Tracking Transparency consent is worth a specific note.

## Not findings

- `NSAllowsLocalNetworking`, the `localhost` ATS exception, and Debug-only settings.
- SDK-required URL schemes and queried schemes.
- `get-task-allow` in the Debug entitlements.
- Absence of jailbreak detection, screenshot protection or `NSFileProtectionComplete` in an ordinary app (hardening notes).
- Usage descriptions that a visible feature uses.
- No Universal Links, when nothing sensitive is delivered through a custom scheme.
